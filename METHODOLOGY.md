# Методология выбора матчей и общие принципы работы

## 1. Общие принципы (Core Principles)

1. **Консерватизм**  
   Предпочтение высокой вероятности прохода над высоким коэффициентом.  
   Целевой диапазон коэффициентов: **1.50 – 2.80** (decimal).  
   Избегаем экстремальных фаворитов (< 1.50) и чистых «лотерей» (> 2.80–3.00 без сильной value-аргументации).

2. **Количество событий**  
   Обычно **1–2** рекомендации в день. Лучше один сильный пик, чем несколько средних.

3. **Приоритет событий**  
   - Когда топ-лиги (EPL, La Liga, Serie A, NBA, NHL топ) имеют мало матчей — смещаемся на нижние лиги, кубки, челленджеры, WTA/ATP 250 и т.д.  
   - Предпочитаем матчи с хорошей читаемостью (форма, травмы, home advantage, статистика).

4. **Источники данных**  
   Всегда используем актуальные данные через поиск/инструменты:  
   - Odds (DraftKings, FanDuel, Covers, Probetrics, Pinnacle и т.д.)  
   - Форма, standings, last 5–10  
   - Injury reports  
   - Goalie/starting pitchers / lineups (где применимо)  
   - Home/away splits, rest days, altitude, back-to-back  
   - Модели и consensus (где доступны)

5. **Оценка вероятности**  
   - Сравниваем implied probability рынка с нашей оценкой.  
   - Ищем лёгкий edge (1–5 %) или просто высокую уверенность при fair odds.  
   - Не гоняемся за большим value, если вероятность ниже ~55–60 %.

6. **Прозрачность**  
   Каждая рекомендация сопровождается:  
   - Точными актуальными коэффициентами  
   - Формой обеих сторон  
   - Ключевыми травмами  
   - Обоснованием (почему именно этот исход)  
   - Рисками

7. **Автосохранение в GitHub**  
   После формирования ежедневных рекомендаций бот автоматически создаёт файл `posts/YYYY-MM-DD.md` в этом репозитории.

## 2. Логика выбора матчей (Selection Process)

### Шаг 1. Сбор расписания
- Ближайшие 24 часа (или до следующего утра по московскому/ригскому времени).
- Спорты: футбол (приоритет нижним), NHL, NBA, теннис (ATP/WTA), иногда другие.

### Шаг 2. Фильтрация по коэффициентам
- Отсекаем всё < 1.50 и > ~2.80–3.00 (кроме явных value-кейсов).
- Смотрим moneyline в первую очередь. Спреды/тоталы — если ML слишком короткий или слишком длинный.

### Шаг 3. Глубокий анализ кандидатов
Для каждого потенциального пика проверяем:

**Форма**
- Последние 5–10 матчей
- Home/Away splits
- Goals For/Against, xG (где доступно)

**Травмы и составы**
- Ключевые игроки out / day-to-day
- Вратари (особенно в NHL)
- Влияние отсутствия на линию

**Контекстные факторы**
- Home ice/court + altitude (Ball Arena и т.п.)
- Rest days / back-to-back
- Travel
- Motivation (начало сезона, playoff race и т.д.)

**Рынок**
- Движение линии
- Consensus / public betting (если есть)
- Sharp books vs soft

### Шаг 4. Сравнение и выбор
- Сравниваем 3–5 лучших кандидатов.
- Выбираем тот, у кого лучшее сочетание:  
  высокая статистическая опора + коэффициент в диапазоне + понятные риски.
- Пример хорошей аргументации:  
  «Атака + дом + высота vs сильный, но не доминирующий соперник» + коэффициент 1.75–1.80 + оценка вероятности 57–60 % vs implied ~55.6 %.

### Шаг 5. Формат выдачи + сохранение
- 1–2 финальных рекомендации
- Полный разбор (odds, form, injuries, prediction, risks)
- Чёткий call (например: Colorado Avalanche ML @ 1.77–1.80)
- Автоматическое создание файла `posts/YYYY-MM-DD.md`

## 3. Примеры сильных факторов (из практики)

- Высота + home advantage (NHL Colorado)
- Тяжёлые травмы у андердога + сильная форма фаворита (NBA)
- Стабильный фаворит в теннисе при коэффициенте ≥ 1.50
- Нижние лиги с явной формой и домашним преимуществом

## 4. Чего избегаем

- Матчи с высокой неопределённостью составов (много ключевых out без ясной замены)
- Экстремальные фавориты (< 1.50)
- «Красивые» истории без статистической опоры
- Большое количество событий в один день

## 5. Адаптация под другой ИИ / сервер

При запуске на другом ИИ:
1. Дать этот файл + STYLE.md как system prompt / контекст.
2. Требовать актуальные данные через поиск (не полагаться на knowledge cutoff).
3. Соблюдать диапазон 1.50–2.80 и лимит 1–2 пика.
4. Всегда указывать источники odds и дату/время проверки.
5. После выдачи рекомендаций — сохранять пост в `posts/YYYY-MM-DD.md`.
